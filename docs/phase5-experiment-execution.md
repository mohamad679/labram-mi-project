# Phase 5 — Real EEG execution and subject-level evidence

## What is verified versus pending

**Already verified in prior live CI:** pinned official LaBraM weight transfer into the 400-sample adapter with finite synthetic logits, and equivalence of MOABB NumPy/Epochs routes for PhysioNet subject 1.

**This phase adds:**
- A public PhysioNet *real-data training smoke* on two distinct subjects. It downloads actual subject recordings, performs a **single optimizer step** on two EEG epochs from subject 1, and checks finite model output for one epoch from subject 2. It saves a sanitized pass/fail report but **no EEG data and no performance metrics**.
- A full multi-seed training planner with `split_seed` fixed at 42, separate from model `seed` (42, 123, 2025 by default).
- Subject-cluster percentile confidence intervals for Accuracy and fixed-label Macro-F1 from real held-out prediction artifacts, using subjects rather than correlated epochs as resampling units.

The bounded CPU smoke **must not** be described as a trained classifier, held-out benchmark or clinical result. It is a pipeline integration check, not a scientific effectiveness study.

## CPU integration check

A GitHub Actions workflow `real-eeg-training-smoke.yml` runs the public-data smoke on relevant pull requests and by manual dispatch. It pins the exact previously verified CPU stack (PyTorch 2.5.1, Torchaudio 2.5.1, Braindecode 1.5.1, MOABB 1.7.2, MNE 1.13.2), uses the immutable LaBraM commit, and uploads only `artifacts/real-eeg-smoke.json`. Raw recordings, label-level predictions and pretrained tensors are never committed or uploaded.

Successful workflow execution proves one real-data gradient step and held-out forward pass work with the pinned stack; it does **not** satisfy the full-data validation gate.

## Prepare a split-locked multi-seed experiment

Choose a separately configured, verified pretrained run. Historical reported numbers remain unverified.

```bash
python -m scripts.run_multiseed --config configs/pretrained_labram.yaml \
  --seeds 42 123 2025 --output-dir artifacts/pretrained_campaign
```

The default action is preparation only, to avoid silently triggering an expensive experiment. For a GPU environment with the authorized dataset, execute:

```bash
python -m scripts.run_multiseed --config configs/pretrained_labram.yaml \
  --seeds 42 123 2025 --output-dir artifacts/pretrained_campaign --execute
```

**Scientific split semantics:** `split_seed` controls the exact disjoint Train/Validation/Test subject partitions and stays 42 across runs. `seed` changes model initialization, stochastic training, and DataLoader shuffle. This comparison fixes the participant holdout, rather than changing test subjects between replicates.

Run the scratch initialization comparison under the **same** `split_seed`:

```bash
python -m scripts.run_multiseed --config configs/baseline.yaml \
  --seeds 42 123 2025 --output-dir artifacts/scratch_campaign --execute
```

Execution saves per-seed training YAML, checkpoints, separate `heldout_predictions.npz` files, and metadata JSON inside gitignored experiment folders. Each full run must be reviewed for sample count, runtime warnings, finite outputs, split identities and matching model/data package revisions.

## Generate evidence-backed intervals

From one genuine held-out prediction artifact:

```bash
python -m scripts.build_benchmark \
  --predictions artifacts/pretrained_campaign/seed_42/heldout_predictions.npz \
  --output-dir artifacts/evaluation_seed_42

python -m scripts.subject_confidence \
  --predictions artifacts/pretrained_campaign/seed_42/heldout_predictions.npz \
  --output artifacts/evaluation_seed_42/subject_ci.json \
  --n-bootstraps 1000 --seed 42
```

`subject_ci.json` contains Accuracy and Macro-F1 point estimates and percentile intervals. It uses the exact test subject IDs in the predictions. **Do not** interpret bootstrapping subjects as a substitute for multiple independent training seeds or as proof of model generalization beyond the underlying cohort.

## Outstanding release gates

1. Complete pretrained and scratch campaigns on the **full eligible dataset** (not the CPU smoke); archive exact environment versions, SHA256 hashes, split manifest, run logs and hardware.
2. Confirm a fixed evaluation protocol, untouched test set and external replication when possible.
3. Report per-class, subject-aware metrics and uncertainty alongside independently confirmed baseline comparisons.
4. Evaluate and disclose the untested scientific assumptions of temporal-prefix adaptation and post-hoc MC Dropout.
5. Only then promote authentic figures and model artifacts to README or a versioned release.

**No new benchmark Accuracy, Macro-F1 or clinical claim is generated by this setup work.**
